## 태양광 셀 은(Ag) 회수 부유선별 설비

폐 태양광 모듈(c-Si)에서 박리한 셀 분획으로부터 **은(Ag)** 을 부유선별로 농축하는
설비의 설계와 계산 코드. 셀 분획을 공급하는 상류 분리설비(DG-HK60)는
[3D 운전 콘솔](docs/drawings/pv-delamination-3d.html)로 별도 정리했다.

- 평균 **0.30 t/h**, 최대 **0.50 t/h** (건조 고체 기준)
- **세척수 bias 연속 부선조 1단, Ø350 mm × 라이저 2.4 m** (대안: 기계식 러퍼·스캐빈저·클리너 3단)
- Ag 회수율 **99.7 %**, 정광 **6.36 kg/h @ 46.3 wt% Ag** (농축비 78배)
- 기액 체류시간 **1 분**, 설치 전력 **6.52 kW** (탈수 보조설비 포함)
- 황화제·pH 조정제·억제제 없음 — 약제는 포수제·촉진제·기포제 3종뿐

### 사용법

패키지가 `src/` 레이아웃이므로 설치 없이 실행할 때는 `PYTHONPATH=src` 를 붙인다.

```bash
PYTHONPATH=src python -m flotation_design                               # 계산서 출력
PYTHONPATH=src python -m flotation_design -o docs/design-calculation.md # 파일로 저장
PYTHONPATH=src python -m flotation_design --peak-tph 0.6                # 처리량 변경
python -m unittest discover -s tests -t .                               # 테스트 (506건)
```

설치하면 `PYTHONPATH` 없이 쓸 수 있다.

```bash
pip install -e .
flotation-design
```

`--average-tph` / `--peak-tph` 를 바꾸면 RFC와 농축·여과 보조설비는 새 유량으로
재산정한다. 기계식 셀 동체는 `design_basis.py` 의 확정 치수를 유지해 새 처리량에서
성능을 계산하며, 목표에 미달하면 계산서에 경고와 필요 치수를 표시한다.

축약차수 입자 애니메이션은 선택 의존성을 설치해 만든다. 이는 CFD/DEM 검증이 아니라
기포 상승·입자 침강·부착/탈착을 보여주는 교육용 모델이다.

```bash
pip install -e '.[simulation]'
python tools/flotation_sim.py fc201-simulation.mp4
```

### 모델에서 알아둘 두 가지

**정광 품위에는 물리적 상한이 있다.** Ag 는 Si 웨이퍼에 소결된 전극이라 부상할 때
Si 코어를 달고 온다. 부상 Ag 1 kg 당 맥석 1.1 kg 이면 상한은 1/(1+1.1) = 47.6 wt%
이고, 문헌의 두 최고 품위(48.8 / 46.7 wt%)가 모두 여기서 멈췄다. 세척수로 제거되지
않으므로 **클리너를 더 붙여도 넘을 수 없다.**

**연속 부선조에는 반응속도 모델을 쓰지 않는다.** 완전혼합조가 아니므로 기액 체류시간
1분을 CSTR 식에 넣으면 Ag 회수율이 63 % 로 나와 실측(~100 %)과 맞지 않는다.
flux 상사로 스케일업하면 수력학적 조건이 보존되므로 실증 측정값을 이월한다.

## 태양광 패널 전처리 플랜트 (상류 공정)

부유선별 앞단에서 폐 모듈을 받아 정션박스·케이블·알루미늄 프레임을 떼어내고 유리를
분리·검사해 레시피별로 적재하는 통합 라인. 설계도는
[docs/drawings/pv-preprocess-plant.html](docs/drawings/pv-preprocess-plant.html) 한 장에
3D 작동 시뮬레이션과 도면 프로그램(2D 제작도·3D 분해도·전체 배치도·도면 목록·부품표)이
모두 들어 있다.

- 영구설비 **58,800 × 8,300 × 5,150 mm** — 셀별 GA 외형에서 파생 (전처리 44,750 + 유리제거셀 GRM-401 14,050)
- JBR–AFR 인계 게이트는 3D 실측 가드-가드 이격(325 mm)에 앵커·심 여유를 얹은 350 mm
- AFR-101 11,500 → 6,900 mm — ±5,750 대칭이던 가드에 여유 475 균등 적용, JBR 출구 롤러와 AFR 베드를 1,800 공용 인계롤러로 직결(셀별 투입 컨베이어 폐지), 프레임 회수함을 90° 횡배치(길이 −1,100 / 폭 +900)
- GBR 버퍼 8,700 → 9,550 mm — 2열 캐리지 X 250 mm 겹침(피치 2,500 < 모듈 2,750)과 위험원을 못 감싸던 안전가드를 3D 실측 피치 2,900 · 여유 475 로 수정
- 스택 → 반전카세트 투입 경로(분리헤드·포획빔·셔틀·승강)를 도면에 전개하고 여섯 단계 시퀀스를 뷰에 표시
- 캐리지 슬롯 적재기 설계 — 데크-도크 순틈(225 mm) 트윈마스트 + 2단 텔레스코픽 콤포크(스트로크 3,200)·선단받이 레일·크로스샤프트 동기. 독립 설계 3안을 기하·운영 렌즈로 적대 심사한 조합안이며 셀 외형 증가 0
- 정션박스 제거(7단계)·프레임 분리(6단계)·슬롯 적재(6단계) 시퀀스를 각 시트 뷰와 표제란에 표시, 3D 적재 애니메이션도 분기→승강→삽입으로 단계화
- AFR 베드-CV-102 사이 2,950 mm 무지지 공백(패널 2,500 초과)을 반출롤러 2,000 으로 폐쇄
- 장비 밴드 Y 0–7,100, 보행·정비 통로 Y 7,100–8,300 (장비 포락선 **밖**)
- 설비 셀 8개 + JB/AFR 인계 게이트 1개, 부품 175품목 (유리제거셀 GRM-401 26품목 포함)
- **반전기 투입 간섭** — 패널이 반전 케이지에 **대각으로** 들어가며 오픈센터 엔드링 단면을 최대 88 mm 파고들고 있었다. 못 잡은 이유가 셋이다 — 간섭 스윕이 시점을 11개만 봤고(관통이 가장 깊은 t 11.5 가 표본 사이로 빠졌다), 링을 바운딩박스로 쟀고(가운데가 뚫린 링은 박스로 못 가린다), 3D 패널이 규격보다 컸다(프레임이 유리 바깥에 붙어 2,615 × 1,515 — 케이지 안지름 2,580 보다 **길어서** 애초에 들어가지 않았다)
- 경로를 **ㄱ자**로 바꿨다 — 링 밑을 수평으로 지난 뒤 두 링 사이에서 수직으로 올린다. 링 평면을 지나는 동안 높이가 변하지 않는 것이 요점이다. 반전축은 3,300 → **3,430** (캐리지 상단과 링 하단 사이 130 → 260 mm), 이송면 **2,290**, 위아래 여유 각각 112 / 116 mm. 패널 프레임은 규격 안으로 넣어 조립체가 2,500 × 1,400 이다
- **4점 단장 클램프의 조**가 링 림(반경 983)에 붙어 물어야 할 패널에서 660 mm 떨어져 있었고, 반전 뒤 하강 경로를 막고 있었다. 패널 장변 프레임 자리(z ∓672.5)로 옮기고 z 여닫이 행정 187.5 mm 를 줬다 — 여는 자리 ∓860 은 패널 반폭 밖이라 승강 경로를 비운다
- **AFR 상부 클램프 포탈** — CL-221 4기(각 3 kN, 합 12 kN)가 y 1,030…1,950 에 서 있는데 **1,950 위가 비어 있었다**. 단축 유압이 프레임을 25 kN/축으로 뽑을 때의 반작용을 받을 구조가 없다는 뜻이다. 기둥 자리는 남은 틈에서 정해진다 — 통과 폭(±700)·정렬 셔틀(±1,100)·LM 레일(±1,040) 밖, 안전가드(±2,330) 안쪽인 **z ±1,450**. 크로스헤드 하면 1,950 이 실린더 상단을 직접 받는다
- 부품표와 3D 의 상호참조를 전수 대조해 **깨진 참조 10행(라벨 20개)** 을 잇고, 참조가 없던 **23행**을 채웠다. 형상이 아예 없던 것은 **VAC-101 이중 진공 스키드·리시버** 하나였다 — BFC 분리헤드와 EOAT 가 진공으로 패널을 무는데 그 진공을 만드는 것이 없었다(§8 의 유압 누락과 같은 종류)
- 기구 간섭은 `node tools/check_clearance.mjs docs/drawings/pv-preprocess-plant.html` 로 검사한다 — 0.5 s 간격 261프레임, 라벨 없는 거울상 포함, 토러스는 축 기준 반경으로 판정. 예외를 늘리려면 `kinematics.DESIGN_CONTACTS`·`PASS_THROUGH` 와 검사 도구 양쪽에 넣어야 하고 테스트가 둘을 집합으로 맞춘다
- **지지·장착** — 3D 메시 1,980개를 인접 30 mm 로 묶어 바닥까지 하중 경로를 따라가면 접지 성분 1개, 예외 3덩어리(로봇이 든 패널·레이저 투영선, 건물 철골이 받는 천장크레인, 건물 벽·기둥이 받는 공압 주관)뿐이다. REV.25 까지는 메시 1,765개 중 덩어리 **77개(144메시)** 가 떠 있었다 — 5단 랙 24메시가 바닥에서 600 mm 뜬 채였다
- 앵커 계획을 문장에서 값으로 승격 — 셀 8개 · 앵커 **190개**(M16 94 / M20 88 / M24 8) · 베이스플레이트·그라우트·레벨링. 표제란 문장은 `mounting.anchor_text()` 가 만들어 모델과 어긋날 수 없다
- 지지 부재 20종 + 지지 브래킷 51개(채번 MB-001…053, 폐번 2). 브래킷은 각 부유 부재와 최근접 접지 부재의 **실측 간격**(중앙값 119 mm)에서 나왔다 — 임의로 세운 기둥은 통과 폭이나 기존 장비를 침범한다
- **CRN-901 5 t 천장크레인** (천장고 12,000 확정) — 후크가 올라가는 높이는 천장고가 아니다. 천장 12,000 − 보 하면 여유 300 − 거더·트롤리 950 = 주행레일 상면 **10,750**, 여기서 C 치수 1,050 을 빼야 후크 최고 **9,700** 이 나온다. 인양물 위로 슬링 **2,520**(폭 2,900 을 60° 로 매단 기하값)과 후크 블록 500 이 더 붙으므로 4,500 짜리 BFC 반전 카세트를 들려면 후크가 7,720 까지 올라가야 한다

- 단계를 가르는 기준은 하나 — **공장에서 확인할 수 있는가.** 정지시간·안전 I/O·압축공기 FAD·전력·앵커 토크는 FAT, 택트·처리량·환기·소음·집진은 라인이 서야 하므로 SAT. 그 사이에 **run-at-rate** 가 하나 더 있다 — 설비가 다 서고 성능도 나오는데 **발주처 실제 반입물로 정격을 유지할 수 있는가**는 또 다른 물음이고, 캠페인 구성비(정상 53 : 깨짐 5 : 전손 2)가 현장과 다르면 §26 의 라벨 공급도 가용률도 통째로 달라진다
- 인수 시점에 **아직 답이 없을 항목 3개**를 미리 표시한다 — S-08 분진 시료(시험 결과는 SAT 뒤에 온다), S-10 내진 미배정 3대(지금 0 이 아니다), R-04 마모율(run-at-rate 로만 나온다). 셋 다 "인수 후 확정" 이 아니라 **"인수 조건에 명시"** 로 다뤄야 나중에 다투지 않는다

- **회사 마크 — 도형과 색을 아트워크에서 직접 뽑았다.** 눈으로 따라 그리지 않았다. `symbol_100x100mm.ai` 는 PDF 1.4 컨테이너라 콘텐츠 스트림에 경로 연산자(`m`·`l`·`c`·`h`)가 그대로 들어 있고, `tools/extract_brand.py` 가 그것을 해석해 절대좌표로 편 뒤 PDF 좌표계(y 위)를 SVG 좌표계(y 아래)로 뒤집고 ArtBox 기준 0…100 으로 정규화한다. 채움 경로 **5개**(파랑 4 · 앰버 1), ArtBox 는 파일 이름대로 정확히 **100 mm**
- **원본 아트워크도 저장소에 있다** (`assets/brand/symbol_100x100mm.ai`) — 추출기만 두고 원본을 두지 않으면 `brand.py` 의 좌표는 확인할 길이 없는 값이 되고, 그 순간 "눈으로 따라 그린 것" 과 구별되지 않는다. 시험이 그 파일의 존재와 PDF 컨테이너 여부를 확인하고, 픽셀 대조 도구는 대조용 PNG 가 없으면 이 원본에서 바로 찍는다 — 새로 받은 사본에서도 `node tools/check_brand_fidelity.mjs` 한 줄로 돈다
- **색도 흉내내지 않았다.** 원본은 ICCBased 4성분(CMYK)이라 RGB 로 옮기려면 프로파일 변환이 필요한데, 그 변환식을 코드에서 다시 쓰면 뷰어마다 다른 값이 나온다. 그래서 원본을 1,200 px 로 래스터화해 **실제 화면 픽셀에서 읽었다** — 파랑 `#228CC9`, 앰버 `#FECA4A`. 인쇄·도장용 CMYK 원값(`C77.6 M34.2 Y1.6` · `M21.2 Y81.5`)은 같이 남긴다
- **픽셀 대조로 검증한다** (`node tools/check_brand_fidelity.mjs`) — 추출 벡터를 **Chromium 이** 래스터화해 원본 PDF 래스터와 픽셀을 센다. 브라우저를 쓰는 이유는 그것이 실제로 이 마크를 그릴 엔진이기 때문이다. 별도 라이브러리로 재면 "라이브러리끼리는 같다"만 확인하고 정작 화면은 확인하지 못한다. **도형 IoU 99.662 % · 색 99.793 % · 안쪽 2 px 완전일치 100.0000 %**(690,764 px 전부 최대거리 0)
- 남는 0.3 % 가 안티에일리어싱인지 좌표 밀림인지는 **해상도를 바꾸면 갈린다** — 안티에일리어싱이면 경계 픽셀이 둘레(∝N)에, 전체가 면적(∝N²)에 비례하므로 불일치 비율이 1/N 로 준다. 400·800·1600·2400 px 에서 `불일치 × N` 이 4.1 / 4.2 / 4.3 / 4.2 로 상수다. 검사기가 실제로 잡는지도 확인했다 — 좌표를 **1 단위** 옮기면 종료코드 1 로 실패한다
- **마크가 적힌 곳은 `src/pv_preprocess/brand.py` 하나다.** 3D 외장 텍스처와 콘솔 SVG 가 그 문자열을 받아 쓴다 — 캔버스 `Path2D` 가 SVG 경로 문법을 그대로 먹기 때문에 가능하다. 도면 파일 안에서도 좌표가 적힌 곳은 `PV_BRAND` 전역 하나뿐이고(도면 프로그램과 3D 번들은 스코프가 달라 그 앞선 전역이 유일한 공유 자리다), **두 파일의 경로가 글자까지 같은지를 시험이 강제한다.** 좌표를 0.1 만 옮겨도, 색을 한 자리만 바꿔도, 명판이 마크를 직접 그려도, `PV_BRAND` 밖에 경로를 베껴 둬도 전부 실패한다(변이 **10/10** 검출)
- **마크는 붙인 것이지 세운 것이 아니다** — 명판 8장이 전부 **이미 서 있던 외장면**에 면일치로 박힌다. 존별 엣지 캐비닛 도어 7면에는 원래 **라벨 없는 주황 띠**(420 × 100 × 20)가 20 mm 나와 있었고 그것을 두께 12 인 명판으로 바꿨으므로 **보행 유효폭은 오히려 넓어진다**. 명판을 달려고 기둥을 세우면 통로를 먹는데, §36 에서 고정 플랫폼을 못 세운 것과 같은 벽이다. 부제는 `layout.build_zones()` 의 존 라벨이라 배치가 바뀌면 시험이 잡는다
- **붙였는데 안 보이면 안 붙인 것과 같다.** 명판만 달아 놓고 전경을 렌더해 보니 **마크가 하나도 읽히지 않았다** — 420 mm 짜리 판이 58.8 m 플랜트의 통로 바깥벽에만 있었기 때문이다. 더 근본적인 이유는 이 플랜트가 **열린 프레임 + 투명 가드**로 모델링돼 있어 로고가 붙을 기계 외장이 아예 없다는 것이다(존 7개 중 통로쪽 불투명 세로면을 가진 곳이 **0개**였다)
- 그래서 셀마다 **마크 데칼 7장**을 통로쪽 안전가드 면에 붙였다(1,200…1,600 mm — 명판의 3~4배). 새 기둥을 세우면 통로를 먹으므로 실제 공장이 하는 대로 **이미 서 있는 가드 면**에 얹었고, 자리는 고른 것이 아니라 각 셀의 가드 면 z 를 3D 로 실측한 값이다. 전부 장비 밴드(z ≤ 3,550) 안이라 보행 유효폭 900 을 건드리지 않는다. GRM 데칼은 처음 자리가 가드 기둥 사이 빈 곳이라 **하중 경로 검사가 떠 있다고 잡았고**, 셀 중앙 기둥 위로 옮겨 판이 기둥을 물게 했다. 시험이 셀마다 하나일 것·1,200 이상일 것·통로를 넘지 않을 것·자기 셀 안일 것을 강제한다(변이 **14/14** 검출)
- **운전 콘솔** (`docs/consoles/pv-preprocess-console.html`) — MCR-901 화면. 셀 상태 7개, 공정·전기·유틸리티·안전·가동 카드, 인수 전 미해결 3항. **화면 값도 손으로 적지 않았다** — `tools/build_console.py` 가 모델에서 36개 값을 찍어 넣고, 시험이 그 값들을 모델과 대조한다. 이 화면은 운전 데이터를 받지 않는다(설계 모델을 띄우는 레이아웃이고, 신호등은 실제 PLC 상태가 아니다)
- **아티팩트는 저장소에서 찍는다** (`python tools/build_artifact.py`) — 발행본을 사람이 만지기 시작하면 그때부터 두 벌이고, 두 벌은 반드시 갈라진다. 그래서 발행은 **저장소 → 기계 변환 → 발행** 한 방향이고, 고칠 일이 생기면 저장소 파일을 고치고 다시 찍어 **같은 URL 로 재발행**한다. 변환기는 골격 태그를 벗기고 벗겨졌는지 스스로 확인하며, **받아 오는 자리**(`src`·`href`·`url()`·`@import`·`fetch`·`importScripts`·`Worker`, 프로토콜 상대 주소 포함)에 외부 주소가 있으면 멈춘다 — 주소처럼 생긴 글자를 전부 잡으면 주석에 적어 둔 근거 링크에 걸려 넘어진다. 아티팩트 이름은 저장소 파일의 `<title>` 이 그대로 간다(변환기가 이름을 짓지 않는다). 시험은 이름이 적혀 있는지가 아니라 **변환기를 실제로 돌려** 막아야 할 6종을 막는지 본다 — `FETCHING` 을 `FETCHING_OFF` 로 바꿔 검사를 꺼도 부분문자열 확인은 통과하기 때문이다

- 전경 렌더 6장 (평면·정면·배면·좌우 측면·조감도) — [docs/renders/](docs/renders/), `tools/render_plant_views.mjs` 로 3D 장면에서 재생성
- 컷어웨이(단면)·분해를 메인 3D 영상과 도면 3D 분해도 양쪽에서 조작 — 절단축 5종(X 상/하류, Y 앞/뒤, Z 위), 절단 위치와 분해 거리는 슬라이더로 조정

배치 수치는 `src/pv_preprocess/layout.py`, 전기 부하는 `electrical.py`, 배선 길이는 `wiring.py`, 비전 구성은
`vision.py`, 안전은 `safety.py`, 분진·고소·내진은 `dust.py`·`access.py`·`seismic.py`,
가동률·검수는 `reliability.py`·`acceptance.py`, 회사 마크는 `brand.py` 가 각각 단일 출처다. 존 X·Y·높이는 셀 외형에서 파생한다. `tests/test_pv_preprocess.py` 가 도면 안의 리터럴과 이 모델을 대조하므로
한쪽만 고치면 테스트가 실패한다. 존이 자기 장비보다 짧아지는 것, 통로가 장비에 덮이는 것,
부품이 자기 외형을 넘는 것은 불변식 테스트로 막는다.
